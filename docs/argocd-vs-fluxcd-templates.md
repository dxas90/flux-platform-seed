# ArgoCD and FluxCD application charts

This repository exposes two independent Helm charts. Register a workload in exactly one catalog so one controller owns its resources.

## Comparison

| Concern | `argocd-template` | `fluxcd-template` |
|---|---|---|
| Stable delivery | ArgoCD `Application` | Flux `GitRepository` + `HelmRelease` |
| Preview resource | ArgoCD `ApplicationSet` | Flux Operator `ResourceSet` |
| Preview discovery | Configured GitHub/GitLab ApplicationSet generator | GitLab `ResourceSetInputProvider` with `GitLabMergeRequest` |
| Preview trigger | Generator reconciliation | Provider polling; optional Flux `Receiver` can reduce latency |
| GitHub previews | Supported when configured | Not implemented by this Flux chart |
| GitLab previews | Supported when configured | Supported for labeled merge requests |
| Catalog | `charts/argocd-template/catalog.yaml` | `charts/fluxcd-template/catalog.yaml` |

The charts intentionally share the basic application fields (`name`, `repo`, `chart`, and `registry`) but their schemas and generated resources are controller-specific.

## Flux GitLab MR flow

The Flux chart follows the Flux Operator GitLab MR guide:

1. A `ResourceSetInputProvider` in `flux-previews` polls the configured GitLab project.
2. Only merge requests carrying the configured opt-in label are exported as inputs.
3. A `ResourceSet` consumes those inputs and generates an isolated preview Namespace, workload RBAC, a commit-pinned `GitRepository`, and a preview `HelmRelease`.
4. The generated GitRepository is pinned to the MR commit SHA, preventing branch movement during a preview.
5. When the MR no longer matches the provider, ResourceSet garbage collection removes generated resources.

The provider API credential and Git clone credential are separate references. Neither credential is projected into application workloads. Preview environments execute merge-request content, so they are intended for trusted repositories and require appropriate admission controls for untrusted contributors.

A Flux `Receiver` may be added separately for lower event latency. Polling remains the default behavior generated by this chart.

## ArgoCD flow

The ArgoCD chart generates an `AppProject` and stable `Application` per catalog entry. Optional Git provider generator settings create an `ApplicationSet` for pull-request or merge-request previews. Provider credentials and project configuration remain external to the chart values.

## Choosing a chart

Use `argocd-template` when the application is owned by ArgoCD or requires ArgoCD's ApplicationSet ecosystem. Use `fluxcd-template` when the application is owned by Flux and the GitLab MR ResourceSet workflow is desired. Do not deploy the same application through both charts.

## Validation

```sh
helm lint charts/argocd-template -f charts/argocd-template/catalog.yaml
helm lint charts/fluxcd-template -f charts/fluxcd-template/values.yaml -f charts/fluxcd-template/catalog.yaml
helm unittest charts/argocd-template charts/fluxcd-template
python scripts/validate.py
python scripts/validate_schemas.py --operator-version 0.61.0
```
